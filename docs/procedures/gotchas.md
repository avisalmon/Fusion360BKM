# Gotchas: what went wrong, and the fix

Numbered once, never renumbered (skills and lessons point at the numbers). Add new rows at the bottom. "How we know"
says whether it was seen here or read somewhere.

| # | Gotcha | Fix | How we know |
|---|---|---|---|
| 1 | A modal dialog in Fusion (update prompt, *Active Sessions Exceeded*, a save question) blocks the main thread; every bridge call waits and then fails with `Timed out after 30s waiting for Fusion main thread (is a modal dialog open in Fusion?)`; `ping` says `blocked` | `python scripts\fusion.py dialog` (reads and clicks with `fusion_dialog.ps1`), or the human clicks it; then retry | seen here, 2026-10 |
| 2 | *Active Sessions Exceeded*: the same Autodesk account has Fusion open on another computer | `fusion_dialog.ps1 -Select 'Suspend*' -Click Continue`, then `-Click Continue`; or close Fusion on the other computer | seen here, 2026-10 |
| 3 | Starting Fusion through `FusionLauncher.exe` runs Autodesk's updater first; a pending update takes about 12 minutes and looks like a hang | wait for the main window; `launch` tells you; the build folder's `Fusion360.exe` skips the updater (but then you run an old build) | seen here, 2026-10 |
| 4 | Fusion's API is in centimetres; a dimension typed in mm comes out ten times too small | never call `adsk` lengths directly from a script; the helpers take mm (`MM = 0.1`) | Autodesk API docs; the helpers were built around it and verified by `body_info()` |
| 5 | The add-in appears **twice** in Fusion's Add-Ins dialog because Fusion sees the junction and the folder; two servers fought for the port | singleton guard in `CopilotBridge.py` plus `allow_reuse_address = False`; the second instance exits quietly. Two entries in the dialog are normal | seen here, 2026-10 |
| 6 | A user parameter named `W`, `H`, `A`, `V`, `F`, `m` or `s` fails with `param name is not valid`: they are unit symbols | word names: `width`, `height`, `wall` | seen here |
| 7 | On the YZ plane, sketch X is model **-Z** and sketch Y is model **+Y** (Z-up); a cutout drawn by guessing the axes landed in the wrong place | sketch in model coordinates (`mpt`, `mrect`, `mcircle`) and `extrude(..., toward=)`; the reference records the mapping | seen here |
| 8 | `new_design()` opens a new tab on every run; after ten runs Fusion has ten Untitled documents | `close_all_untitled()` at the top of a run; `close_doc(save=False)` for one | seen here |
| 9 | Saving to the Autodesk cloud from the API did not work in this setup | `export_f3d` to disk; save by hand if the cloud copy matters (the save dialog is modal: gotcha 1) | seen here; cause not established |
| 10 | Editing `CopilotBridge.py` does nothing until Fusion restarts; editing `bridge_helpers.py` takes effect on the next call | restart Fusion after a server change (`fusion.py launch` after closing); helpers never need it | by design, seen here |
| 11 | A fillet on the bottom edges, or a shell before the outside fillets, makes a part that prints badly or has sharp inside corners | fillet the vertical edges only (a `predicate` on the edge direction), then shell from the top; the mentor checklist asks | [community] FDM guidance; the template does it this way (unprinted) |
| 12 | The modelling orientation (Z-up or Y-up) is baked into a document when it is created; a document made before the bridge set the preference may have its "top" on another axis | the bridge sets Z-up at start-up; check `body_info()` bounding boxes rather than assuming which axis is up in an old document | seen here |
| 13 | A folder with a running process in it cannot be renamed on Windows (`being used by another process`): the app session's shell has the repo as its working directory | copy with `robocopy` to the new name, re-point the AddIns junction (`fusion.py install`), leave a pointer in the old folder, delete it after the session closes | seen here, 2026-10-27 (renaming `Fusuin360` to `Fusion360BKM`) |
| 14 | `Remove-Item` and a `create` of the same file in parallel raced: the create saw the old file and refused | do delete-then-create sequentially | seen here, 2026-10-27 |
| 15 | PowerShell 5.1 has no `&&`; a `gh --jq` expression with `\(` breaks quoting | `;` plus `$LASTEXITCODE`; `gh --json ...` piped to `ConvertFrom-Json` | seen here |
| 16 | A script run through the bridge (`fusion.py run` / `exec`) sees the helpers' public names only: `_app` raised `NameError: name '_app' is not defined` | use `app`, `design()`, `root()`, exactly as the skills' recipes write them | seen here, 2026-10-27 (camera script for `06_sketched_box`) |
| 17 | Electronics text commands (`app.executeTextCommand("Electron.run ...")`) return an empty string whether they worked or not: `ADD R-US_0805@rcl` placed nothing and said nothing | after every command, read the result back through `adsk.electron` (parts, nets, grid) and treat "nothing changed" as the error | seen here, 2026-11-16 |
| 18 | `fusion.py shot` raises `'NoneType' object has no attribute 'fit'` in a schematic or 2D PCB: those editors have no 3D viewport | capture the Fusion window with Windows (PrintWindow) | seen here, 2026-11-16 |
| 19 | Shift+S and the Utilities menu do nothing on Fusion's Home screen, so "enable the add-in from Scripts and Add-Ins" fails there | with no document open nothing can be lost: close Fusion and `fusion.py launch`; the manifest's `runOnStartup` starts the bridge | seen here, 2026-11-16 |
| 20 | The classic EAGLE library names (`rcl`, `led`) are not Fusion's managed libraries; parts must be named as the Place panel shows them (`<component><variant>@<library>`) | look the part up first; our own library (backlog E3.5) removes the guessing | seen here, 2026-11-16 |
| 21 | `VALUE` on a part whose library fixes its value (`userValue` false: a connector, an LED) opens a modal "Part 'J1' has no user definable value. Change it anyway?"; the bridge waits behind it | `ecad_open` sends `SET CONFIRM YES`, so EAGLE answers its own yes/no questions and `VALUE` works on any part (verified 2026-11-17: D1 got "RED 5MM" with no dialog); `fusion.py dialog -Click No` frees a stuck bridge | seen here, 2026-11-16 |
| 22 | `ADD` of a part whose technology is `_` (Fusion's own `Resistor` library, some Tinkercad parts) raises "Fusion Electronics has detected an unexpected condition ... PlacePartWorker.cpp, Line 23. Condition: assetAdded" and places nothing; same with the `_` left off | `fusion_parts.py` marks them "crashes ADD"; pick an equivalent without `_` (or place by hand); `fusion.py dialog -Click OK` | seen here, 2026-11-16, Fusion 2706.1.17 |
| 23 | `fusion.py dialog` failed with "Cannot convert ... AutomationElementCollection to ... SwitchParameter": PowerShell names ignore case, so `$all` was the `-All` switch | renamed to `$elements` | seen here, 2026-11-16 |
| 24 | A new board editor works in **mil**: `MOVE (100 0) (30 0)` meant 2.54 mm to 0.76 mm, so it grabbed the corner at 0,0 instead of the one at 100 mm | `ecad_open` sends `GRID MM ON` for the schematic and the board; read the grid back (`grid.unit` 1 = mm) when in doubt | seen here, 2026-11-16 |
| 25 | `Board.deleteEntities` (with `beginDesignChange`) on the outline wires raised "unexpected condition" dialogs that came back as fast as they were closed; Fusion had to be killed and offered "Recovered Documents" on restart | never delete through the API; change the outline by dragging corners (`brd_outline`); `fusion.py dialog -Click Close` dismisses the recovery list | seen here, 2026-11-16 |
| 26 | Tracks are not drawn exactly as sent: Fusion's router moved a corner 1.2 mm from the board edge to 1.27 mm and replaced the right angles with 45-degree bends; `SET WIRE_BEND 2` and one `WIRE` per piece did not change it | explained 2026-11-17: Fusion's default Board Outline Clearance is 1.02 mm, plus half the 0.5 mm track = 1.27 mm. Design so the rules have room; trust `brd_report()` and the screenshot, not the points sent | seen here, 2026-11-16 |
| 27 | `Electron.run DRC` opens Fusion's QML "Design Rules" dialog, which only shows and saves the rule set (it does not check), blocks the bridge, and whose buttons UI Automation cannot see (`fusion.py dialog -Click OK` finds nothing) | never send `DRC`; the rules travel with the board and `pcb_check.py` reads them from the export; `brd_errors()` runs the check. If the dialog is open, click its OK by screen position (it sat at 957, 767 in the dialog) or press Escape | seen here, 2026-11-17 |
| 28 | `Electron.mfgexport <dir> <job>` on an unsaved design fails with "CAM output directory does not exist or is empty"; once saved it answers "CAM output generated." but writes to `<parent of dir>/<job name>/<job name>.gbr/CAMOutputs/...`, not to `<dir>` | `ecad_save()` first; `cam_export()` runs it in a scratch folder and copies the files out; no spaces in either path | seen here, 2026-11-17 |
| 29 | Fusion refuses edits that break its rules, silently: a `WIRE` across another signal stopped 0.15 mm short of it, and a `HOLE` on a track was not placed (an interactive HOLE panel stayed open instead) | read back after every write; the independent `pcb_check.py` is the proof, not the absence of an error in Fusion | seen here, 2026-11-17 |
| 30 | Saving an electronics design makes three cloud files (`.fprj`, `.fsch`, `.fbrd`), and Fusion allows two designs with the same name: rebuilding board 10 and saving it again made a second set beside the first | `ecad_save()` adds the date and time when the name is taken; delete old copies in Fusion's Data Panel by hand | seen here, 2026-11-17 |
| 31 | Fusion's Gerber fills a flat-ended thick arc (the LED's outline) with about 2,250 strokes of a 0.0254 mm aperture, so a naive check reports a 0.025 mm silkscreen line | `factory_check.py` treats a hairline aperture used for more than 20 strokes as a fill, and reports the thinnest real line | seen here, 2026-11-17 |
| 32 | `Board.checked` stays False even after *Check Design Rules* ran (the Schematic's `checked` turns True after the ERC) | judge the board check by its error list (`brd_errors()`), not by `checked` | seen here, 2026-11-17 |
| 33 | Fusion's CAM job puts non-plated mounting holes into the one plated drill file, so the fab plates them | `factory_check.py` warns (NPTH-PLATED); fine for screws (approve it in `checks.json`), otherwise ask the fab or split the drill output | seen here, 2026-11-17 |
